## Findings

### F1 — Horizontal layering; no walking skeleton (critical)
~5,240 LOC of probes, contracts, fakes, and redaction exist. `src/voxflow/__main__.py` only emits a diagnostic. Nothing connects shortcut → microphone → ASR → text in the focused app. The roadmap defers insertion to Phase 4, so the riskiest integration (Wayland paste) would be proven last.

### F2 — Phases are marked complete without being proven (critical)
`01-wayland-foundation/HOST-ACCEPTANCE.md` and `02-local-dictation-engine/02-HOST-ACCEPTANCE.md` have every host checkbox unticked. `02-VERIFICATION.md` marks AUDIO-04 "Human needed". REQUIREMENTS marked PLAT-02 and AUDIO-01 `[x]` while traceability said "live validation pending". The offline fake suite is green, but it can't show that a user can do anything.

### F3 — The live runtime dependencies aren't installed (critical)
- `import dbus_next` and `import sounddevice` both fail in `.venv`; neither is in `pyproject.toml`.
- `gi` (PyGObject/GTK4) isn't importable from `.venv` because it's system-only and the venv has no system site-packages.

The portal, shortcut, and audio adapters can't run outside fakes.

### F4 — The insertion strategy doesn't work on GNOME 50 (critical)
The roadmap and CLAUDE.md said "wl-clipboard clipboard-first" with `wtype` as optional. On this exact host class this fails:
- Handy **#1742** (Ubuntu 26.04, GNOME 50.1, Intel iGPU): every paste method fails. GNOME doesn't implement `ext-data-control` / `wlr-data-control`, so background clipboard writes fall back or need focus.
- Handy **#1549**: `wl-copy` hangs on GNOME Wayland, and keycombo paste selects `wtype`, which fails.
- `wtype` needs `zwp_virtual_keyboard_v1`, which Mutter doesn't implement (Handy #2006, #429).
- `ydotool`/`dotool` need write access to `/dev/uinput`, which is root-only here. That means a privileged setup step and a security trade-off.

**Supported path on this host:** an `org.freedesktop.portal.RemoteDesktop` session (keyboard only, `persist_mode=2` restore token). In the same session, `org.freedesktop.portal.Clipboard` gives clipboard ownership without window focus, and `ConnectToEIS` gives a libei keyboard device for Ctrl+V.

### F5 — Host-app portal identity is missing (high)
There's no `org.freedesktop.host.portal.Registry.Register` call and no `.desktop` app ID. Unsandboxed apps get an empty or guessed app ID. GNOME keys GlobalShortcuts bindings and RemoteDesktop restore tokens per app ID, so binding and persistence are unreliable without one. Handy #1555 tracks this and cites it as a reason for Flatpak.

### F6 — The ASR default is unmeasured and probably too slow (high)
The only Whisper model on disk is `medium.en`. On CPU INT8 that's expected to take well over 1 s for a 5–10 s utterance. Wispr-class feel needs text roughly 0.5–1 s after release. Handy ships Parakeet as its fast default. `tools/asr_benchmark.py` exists but has never run on this host.

### F7 — No feedback/overlay design that works on GNOME (medium)
GNOME doesn't support `wlr-layer-shell`. A GTK4 window can't be a non-focusable positioned "flow bar". Presenting one takes focus and breaks the paste target (Handy #315, #1375).

## Handy issue evidence (public tracker, retrieved 2026-10-17)

| Issue | Symptom | Lesson for VoxFlow |
|---|---|---|
| #1742 | GNOME 50.1 auto-paste fails; text only on clipboard | Don't rely on data-control clipboard tools on GNOME |
| #1549 | wl-copy hangs; wtype chosen and fails, no fallback | Capability-detect; never offer wtype on GNOME |
| #1555 | META: Wayland insertion/hotkeys fragmented | Pick one compositor-supported path per desktop; register app identity |
| #429, #439, #2004 | Lost first character; wrong layout; hardcoded Ctrl keycode | Paste with one Ctrl+V chord, not per-character typing; resolve keycodes from the compositor keymap; inject only after the trigger key is released |
| #502 | Pasted old clipboard; restore raced the target app | Delay restore, restore only if we still own the selection, make restore optional |
| #2072 | Transcripts pollute clipboard history | Mark temporary selections sensitive where supported |
| #2268 | Empty LLM output silently dropped dictation | Empty/failed cleanup → raw transcript |
| #2275 | Logged success when paste reached nothing | Report "sent", not "delivered"; keep text in history |
| #806, #2113 | cpal/ALSA capture fails or stalls on PipeWire | Use PipeWire-backed capture with a stall watchdog |
| #1973 | Leaked PipeWire playback streams wedge the graph | One reusable feedback stream, or none in v1 |
| #102 | Shortcut not working on Ubuntu | Use the portal; report binding failures clearly |
