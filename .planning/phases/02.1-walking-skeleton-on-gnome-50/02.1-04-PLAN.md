## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> model files | Large binary artifacts fetched from third-party hosts |
| manifest -> filesystem | Manifest paths decide where files are written |
| model file -> inference runtime | Untrusted model weights parsed by CTranslate2 / onnxruntime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-10 | Tampering | download_model | mitigate | Per-file SHA-256 from the pinned manifest checked before rename; mismatch deletes file; https only; same-host redirect rule |
| T-02.1-11 | Information Disclosure | download_model | mitigate | Explicit user command + `--yes`/prompt stating hosts and size; never auto-run, never in tests, no telemetry or identifying headers |
| T-02.1-12 | Tampering | path handling | mitigate | Reject absolute / `..` manifest paths and ids with separators; resolve and confirm path is inside models root |
| T-02.1-13 | Tampering | supply chain (pip) | mitigate | Uses plan 01 pinned sherpa-onnx; no new installs in this plan |
| T-02.1-14 | Denial of Service | partial downloads | mitigate | `.part` files + resume; install marker only after all hashes verify |
| T-02.1-15 | Tampering | malicious model weights | accept | Hashes pinned to maintainers' official repos; manifest is the trust root; documented in README |
| T-02.1-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan; sherpa-onnx legitimacy checked in 02.1-01 |
