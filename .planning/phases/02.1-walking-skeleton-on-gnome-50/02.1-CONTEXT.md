# Phase 02.1: Walking Skeleton on GNOME 50 - Context

**Gathered:** 2026-10-17 (from the systems audit, `.planning/research/AUDIT-2026-10-17.md`)
**Status:** Ready for planning (discussed `--auto` 2026-10-17; D-01..D-11 from audit, D-12..D-17 added from user product criteria)

<domain>
## Phase Boundary

Hold the shortcut, speak, release, and the **raw** transcript lands in the focused app on the target host. Target apps: GNOME Text Editor/gedit, a Firefox textarea, GNOME Terminal. This phase proves the whole vertical slice end to end with the simplest component at each layer. No cleanup, styles, dictionary, history UI, settings UI, or overlay.

**Product north star (user, 2026-10-17):** a Wispr Flow + Handy hybrid. Wispr Flow's workflow (hold a key, speak, release, polished text appears in whatever app has focus) with Handy's **model catalogue** (browse, download, select, and switch local speech models). This phase delivers the thinnest working version of both: the dictation loop, and a catalogue the loop reads its model from.
</domain>

<decisions>
## Implementation Decisions

### Runtime
- **D-01:** Add `dbus-next`, `sounddevice`, and `numpy` to `pyproject.toml` / `uv.lock`, pinned.
- **D-02:** GTK isn't required in this phase. If a fallback window is needed, the venv uses `--system-site-packages` for the distro PyGObject, documented in the README.
- **D-03:** A single long-lived user daemon, `python -m voxflow daemon`, keeps the model warm. Ship a systemd `--user` unit file but don't auto-enable it.

### Identity
- **D-04:** Install `dev.voxflow.VoxFlow.desktop` to `~/.local/share/applications/`. Call `org.freedesktop.host.portal.Registry.Register("dev.voxflow.VoxFlow", {})` before any other portal call.

### Trigger
- **D-05:** GlobalShortcuts v1 `CreateSession` + `BindShortcuts` with one `dictate` shortcut. `Activated` → start, `Deactivated` → stop. If `Deactivated` isn't observed on release on this host, use toggle mode and record that result in HOST-ACCEPTANCE.

### Capture
- **D-06:** `sounddevice` at the device's native rate, resampled in memory to 16 kHz mono. Open the stream on press and close it on release. Never keep the mic open while idle. Add a stall watchdog: no frames for 500 ms means a structured failure.

### ASR
- **D-07:** Benchmark three candidates on this CPU with `tools/asr_benchmark.py`:
  - `faster-whisper small.en` int8
  - `distil-large-v3` int8
  - Parakeet-TDT-0.6B-v3 via `sherpa-onnx` (new provider)

  Choose the default by p50 release→text latency for a 6 s utterance (target < 700 ms) and accuracy on the fixture set. `medium.en` is the accuracy reference, not the default.

### Insertion (GNOME)
- **D-08:** One RemoteDesktop portal session, created at daemon start:
  1. `CreateSession`, then `SelectDevices(types=KEYBOARD(1), persist_mode=2, restore_token=<stored>)`
  2. `Clipboard.RequestClipboard`
  3. `Start`, keeping the returned `restore_token` (0600 file under `$XDG_STATE_HOME/voxflow/`)
  4. `ConnectToEIS`
- **D-09:** Each paste:
  1. Wait for trigger release.
  2. `Clipboard.SetSelection({mime_types: [text/plain;charset=utf-8, text/plain]})`.
  3. Serve `SelectionTransfer` via `SelectionWrite`/`SelectionWriteDone`.
  4. Send the Ctrl+V chord through the EIS keyboard. Resolve keycodes from the EIS-supplied keymap with xkbcommon; never hardcode them.
  5. Don't restore the clipboard in this phase.
- **D-10:** The insertion result is `sent` / `denied` / `unavailable` / `failed`, never "delivered". On anything but `sent`, keep the text and print/notify "copied — press Ctrl+V".
- **D-11:** The terminal needs Ctrl+Shift+V. Detecting the focused app isn't available on GNOME Wayland without an extension, so for now record the terminal result as a known limitation. Revisit in Phase 4 (configurable chord, or a Shell extension).

### Product shape (added from user criteria)
- **D-12:** Wispr-style flow is the contract: global hold-to-talk, no window to focus, text pasted at the cursor of the focused app. Toggle mode is the fallback only (D-05). Cleanup/polish is Phase 3; this phase pastes the raw transcript.
- **D-13:** **Model catalogue** is a pinned, offline-readable manifest (`src/voxflow/providers/catalog.json`) listing each model: id, display name, engine (`faster-whisper` | `sherpa-onnx`), languages, size on disk, expected speed/accuracy tier, source URL, and SHA-256. Seeded with the three benchmark candidates (small.en, distil-large-v3, Parakeet-TDT-0.6B-v3) plus the existing medium.en as the accuracy reference.
- **D-14:** Catalogue operations are CLI-first in this phase: `voxflow models list | download <id> | use <id> | remove <id>`. Download is an explicit user command (never automatic, never in tests), resumable, verifies SHA-256, and states the network use before starting. The selected id is stored in the SQLite settings.
- **D-15:** The daemon loads whichever model is selected, so switching models is `models use <id>` plus daemon reload, with no code change. The benchmark (D-07) runs over installed catalogue entries and its results are recorded back in the catalogue listing (measured p50 on this host), which is how the default is chosen.
- **D-16:** Both ASR engines sit behind the existing `ASRProvider` interface (`providers/asr.py`). Parakeet via sherpa-onnx is a new provider class; the catalogue maps `engine` to provider.
- **D-17:** Catalogue GUI (browse, progress bars, per-model benchmark badges) is NOT in this phase. It lands with the Phase 5 settings UI, reading the same manifest and settings, so no rework.

### Claude's Discretion
- How to bind libei: ctypes over `libei.so.1` for the handful of calls needed (context, seat bind, device keyboard, keymap fd, key, frame), or an existing Python binding if one is packaged. Keep it to one module.
- Whether the daemon prints status to stdout or uses `org.freedesktop.Notifications`.
</decisions>
